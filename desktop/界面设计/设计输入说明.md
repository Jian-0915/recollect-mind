## 1\. 项目定位（一句话）

**陪伴对话桌面应用**：记忆内核已是成品，桌面端是它上面的壳；后续会在此之上扩展模块（带我听歌、控制电脑、自动选音乐）。

**职责边界**：

-   桌面端 = 陪你聊、记得你、主动想起你 + **agent 本身的人格/性格设置**。
-   web 端 = 你查它、管它（记忆 / 图谱 / 人物 / 关系 / 概念 / 成长 / 数据等管理页仍在 web，不进桌面端）。
-   设置界面只针对 **agent 这个人**（人格、性格、说话方式），不是记忆管理后台。

* * *

## 2\. 对话窗口（核心主界面）

**功能清单**：

| 功能 | 说明 |
| --- | --- |
| 发消息 / 收回复 | 输入回车发送，走真写通道 `/api/live`（不能退回只读的 `/api/ask`） |
| 历史回填 | 启动加载 `/api/live/history`，关掉重开对话还在 |
| 记忆回执 | 每轮回复下方淡淡一行"已记住…"，让被记住可感知 |
| "在想…"状态 | 等待回复时的轻提示 |
| 主动关心气泡 | 它主动开口，带"回应 / 忽略"；回应把话题填进输入框，由你确认发送 |

**要画的状态**（同一窗口的几种形态）：

-   空状态：还没对话时的一句引导
-   对话中：消息流（你 / 阿澈 / 主动 三种气泡）
-   等待回复：在想…
-   主动关心：插入一条主动气泡

## 3\. 弹窗窗口（⚠️ 需你确认指哪一种）

"弹窗窗口"有几种可能，请明确是哪一类（可多选）：

-   **A. 主动关心弹窗**：它想起你时，屏幕浮出一张小卡片（可回应 / 忽略），不打断当前窗口。
-   **B. 全局悬浮窗 / 悬浮球**：常驻桌面，随时点开对话，像语音助手的唤起入口。
-   **C. 设置模态弹窗**：点设置后从对话窗浮出的层，而非独立页面。
-   **D. 其他**：你脑子里另有形态，直接描述。

确认后我再补对应的尺寸、层级、触发/消失规则。

## 4\. Agent 设置界面（人格 / 性格）

可直接复用 web 端「人设」页的字段。以下是**真实字段与接口**，设计时照此布局即可；字段取舍由你定——可以全抄，也可以只留核心的人格 / 性格项。

**人设卡字段**（对应 `GET/PUT /api/persona`）：

| 分组 | 字段 |
| --- | --- |
| 基本 | 名字、身份一句话、性格（逗号分隔，最多 8 条） |
| 说话方式 | 风格、长度、怎么称呼对方、口头禅、避免 |
| 关系与相处 | 对方称呼、关系定位、主动性、关心方式、情绪基线、绝对不做 |
| 示范语气 | 2 组「对方说 / 我回」（只学语气，不当真实经历） |

**固定身份宪法**（5 项，对应 `PUT /api/identity`）：我是谁、我服务谁、称呼与边界、语气与禁忌、能力边界。优先级高于人设。

**操作按钮**（web 端现状）：保存新版本、预览注入文本、填入示例、清空为骨架、放弃修改/重新读取、版本历史/回滚。

**生效规则**：保存人设后调 `POST /api/live/reset` 立即生效，无需重启（历史踩过"后台改了人设、对话还是旧人格"的坑，必须接）。

**相关接口**：  
`GET/PUT /api/persona` · `POST /api/persona/preview` · `GET /api/persona/history` · `POST /api/persona/rollback` · `PUT /api/identity` · `POST /api/live/reset`

## 8\. 逻辑层已就绪（2026-11-17，工程侧）

桌面端要用的接口已封装成 `desktop/web/logic.js`，UI 不用碰接口细节。设计稿只需引一行：

```html
<script src="/desk-assets/logic.js"></script>

```

然后调 `DeskAPI.xxx()`（全部返回 Promise）：

| 分类 | 方法 |
| --- | --- |
| 对话 | `chat(q)` · `history(limit)` · `liveStatus()` · `resetLive()` |
| 主动关心 | `proactive()` · `proactiveStat()` |
| 人设 | `persona()` · `personaTpl(example)` · `personaPreview(card)` · `personaSave(card)` · `personaHistory(limit)` · `personaRollback(v)` |
| 宪法 | `identity()` · `identityHist(limit)` · `identitySave(profile)` |
| 模型 | `settings()` · `settingsSave(payload)` · `models()` |
| 桌面壳 | `meta()` · `notify(title, msg)` · `openWeb()` |

**关键约定**：

-   对话只调 `chat()`（内部走 `/api/live` 真写），不要自己拼 `/api/ask`。
-   人设保存只调 `personaSave(card)`：它内部**先校验 → 再保存 → 自动 reset**，一步到位，避免"改了不生效"。
-   `notify()` 在非 pywebview 环境自动静默，不会报错。

**已做真实只读验证**：人设 v5「阿澈」已生效、宪法 v2 校验通过、主动/对话状态接口正常。

**静态资源**：原来的 `/desk-assets/` 已改为整目录挂载 —— `desktop/web/` 挂在 `/desk/`，
页面与 assets 用相对路径即可（`assets/tokens.css` → `/desk/assets/tokens.css`）。
访问 `/desk` 会自动 307 到 `/desk/`。

### 9.1 换掉了哪些假数据

| 位置 | 原型 | 现在 |
| --- | --- | --- |
| 启动 | 静态示例对话 | `DeskAPI.history(40)`，按 30 分钟间隔插时间戳；无历史才显示空状态 |
| 发送 | `replyFor()` 关键词假回复 | `DeskAPI.chat(text)` 真写通道；失败收回气泡、原文放回输入框、错误条可重发 |
| 记忆回执 | 写死的"已记住 · …" | 取 `remembered_count / merged / backdated` 三种措辞；没记住就不显示回执 |
| 主动关心 | 写死卡片 + 10 秒假轮询 | `DeskAPI.proactive()` 每 60 秒取一次（首轮延后 10 秒），非模态不抢焦点，同时最多一张 |
| 顶栏名字/印章 | 写死"阿澈/澈" | `DeskAPI.persona()` 取名字，印章取名字末字 |
| 设置页全部字段 | 写死的示例卡 | `DeskAPI.persona()` 回填；保存 `DeskAPI.personaSave(card)` |
| 版本历史 | 三条写死记录 | `DeskAPI.personaHistory(20)`，前端补一行真正的"当前"，旧版可点恢复 |
| 注入预览 | 前端拼字符串 | `DeskAPI.personaPreview(card)` 返回后端真实渲染文本 |
| 填入示例 / 清空 | 前端内置示例 | `DeskAPI.personaTpl(true/false)`，与后端模板同源 |

### 9.2 设计稿与后端不一致的地方（已按后端为准处理）

1. **风格/长度/关系/情绪是药丸单选，后端是自由文本**
   选中 → 写成一句固定话术；若库里存的是"对不上任何档位"的文本，则一个都不选中，
   并在下方显示「当前设定：…（不是预设档位，保存时按原文保留）」，保存时原样写回。
   **不会因为界面没有这个选项就把你的设定改掉。**

2. **「主动性 1–5」滑杆**
   后端没有"弹窗频率"这个可写项（`TICK_MINUTES` 在环境变量里）。滑杆实际写的是
   `relationship.initiative` —— 即"它说话时有多主动"，不是弹窗多久来一次。
   滑杆没动过时保留原文，动了才覆盖成档位话术。

3. **「恢复历史版本」**
   后端 history 只返回版本号/时间/原因，不返回卡片正文，无法"填回表单再保存"。
   所以恢复直接调 `personaRollback(v)`：生成一个新版本，旧版不删 ——
   与设计稿文案"恢复会生成一个新版本"一致，但与 README 里"落到表单仍需保存"的描述不同。

4. **宪法没有独立保存按钮**
   设计稿只有一个「保存新版本」。现在的做法是：点保存时先存人设，再检测宪法五项是否改过，
   改过才单独提交；没改不会触发宪法的校验，避免"没动它却被拦住"。
